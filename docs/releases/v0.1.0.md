# Crafleet 0.1.0

Crafleet 0.1.0 is the first public release of the cross-platform CLI for managing Paper and Velocity servers as reproducible projects. It keeps declarations and reviewed configuration in Git while separating active runtime state from updates prepared for the next managed deployment.

## Install

Crafleet 0.1.0 requires Node.js 24.20.0 or later and earlier than Node.js 27, plus the Java version required by the selected Minecraft server.

```sh
npm install --global crafleet
crafleet --help
```

Install Crafleet on the server host. It does not install Java, establish SSH connections, or register operating-system services.

## Reproducible servers and plugins

Each project declares its Paper or Velocity server, plugins, configuration, secrets, and backup policy in `crafleet.yaml`. Resolved server and plugin artifacts are pinned by source, version, size, and SHA-256 in `crafleet-lock.yaml`, so an existing lock can be installed again without silently selecting newer upstream files.

Plugin artifacts can come from Modrinth, Hangar, SpigotMC, GitHub Releases, or local files. Crafleet reads Bukkit, Paper, and Velocity descriptors without executing the JAR, verifies the artifact, and keeps shared content-addressed cache entries separate from each server's active installation.

Configuration capture compares the reviewed base, the previous observation, and the current runtime. Conflicts remain explicit, registered secrets are replaced with references before files enter managed state, and changed configuration is staged for review before deployment.

## Safe updates, backups, and recovery

Server and plugin changes are prepared as a pending installation while the current JARs keep running. A managed restart gracefully stops the server, creates the required cold backup, applies the complete pending installation, and starts the new active version. Deployment and restoration journals allow interrupted operations to be diagnosed and recovered deliberately.

Encrypted restic repositories support file data together with SQLite databases and InnoDB-only MySQL and MariaDB databases. Connections outside loopback require a configured CA certificate, and database writers that Crafleet does not manage must already be stopped. Restore first extracts into a separate directory for inspection; applying a restore takes another safety backup, restores the snapshot's recorded active installation, and leaves the server stopped for review.

Workspaces manage multiple independent projects from one CLI invocation. Servers that share data or a database can join one backup group so Crafleet stops every managed group member before creating or restoring a coordinated snapshot.

## Operations

Commands provide concise human-readable output by default and stable JSON for automation. Dry-run and offline modes, artifact inventories, deployment plans, `doctor`, and explicit recovery commands keep network access and state changes visible.

The interactive console opens at recent output, loads older history on demand, accepts server commands, and detaches without stopping Java. Paper EULA consent can be recorded once for the current user and Crafleet home, while non-interactive use requires explicit confirmation.

## Compatibility

Crafleet runs on Linux, Windows, and macOS. Automatic restic setup supports Linux x64 and arm64, macOS x64 and arm64, and Windows x64; restic-backed operations are unavailable on other architectures in this release.

Server compatibility follows the Java requirement and upstream artifact selected in each project rather than a hard-coded Minecraft version list. Crafleet manages Paper and Velocity server artifacts but does not replace their own compatibility requirements.
